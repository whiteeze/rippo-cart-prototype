Корзина и оформление заказа: ключевые проблемы

Наблюдения — по текущему сайту и публичным правилам. Гипотезы — отдельно, требуют проверки аналитикой/интервью.

Приоритет Проблема Тип Предлагаемое решение
P1 Неясно, сколько платить сейчас и сколько при получении. На сайте одновременно заявлены «оплата при получении», бесплатная доставка до ТК/Почты и тарифы СДЭК при оформлении. Покупатель не видит единого понятного итога до подтверждения. наблюдение В сводке заказа всегда три явные строки при COD: «Оплатить сейчас», «Оплатить при получении», «Общая стоимость». Неизвестную доставку не показывать как 0 ₽ / «бесплатно» в итоге.
P1 Ошибки и пересчёт доставки не объяснены. ТЗ фиксирует сбои расчёта СДЭК/Почты; текущий UX не показывает понятные состояния «считаем / недоступно / сервис не отвечает». наблюдение + ТЗ Отдельные состояния доставки с текстом и действием (исправить адрес / повторить / выбрать альтернативу). Старый расчёт инвалидировать при смене адреса или состава.
P2 Мини-корзина в шапке показывает только сумму «0 ₽». Количество позиций и состав скрыты до открытия панели; пустое состояние есть, но путь «посмотреть → изменить → оформить» неочевиден на мобильном. наблюдение В шапке: бейдж количества + сумма со скидкой. В панели: позиции, −/+, удаление, CTA «Оформить заказ». Суммы шапка = панель = страница корзины = оформление.
P2 «Комплект» легко спутать с «штуками проставок». Товар продаётся комплектом; без явной подписи количество воспринимается как отдельные проставки. гипотеза (подтвердить на карточках/корзине) Везде подпись «N комплект(ов)», цена «за комплект», в строке позиции — «стоимость комплектов».
P3 «Быстрый заказ» может выглядеть как полноценная покупка. Если фактически уходит заявка, покупатель ожидает оплату/трек — растёт нагрузка на поддержку. гипотеза Явный текст: «Заявка менеджеру. Это не оплаченный заказ». Связь с основным оформлением: кнопка «Оформить самостоятельно».
Вне скоупа исполнителя: диагностика API СДЭК/Почты/ТБанка, правка CMS, коммерческие правила скидок. Персональная скидка авторизованного покупателя имеет приоритет над общей (текущее правило сохраняем). Совместимость промокода с скидками — на согласование (см. вопросы).

Рекомендация по форме: один экран с последовательными блоками (получатель → способ доставки → адрес → оплата → сводка). Оформление только для авторизованного покупателя (гостя нет). Закреплённая сводка справа (desktop) / снизу (mobile) держит итог в фокусе.
